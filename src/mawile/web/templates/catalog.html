Audit Flow

Evidence Lanes

What the report is designed to separate

Invariant stability

Meaning-preserving perturbations should keep the verdict stable. These perturbations drive flip risk, signed score shifts, and invariant risk themes.

Directional degradation

For pointwise judges, edits that make a response worse relative to its task should receive worse scores or labels. These probes measure degradation detection, missed degradations, and contradictions.

Gold standard correctness

Trusted labels are not perturbations. They measure baseline judge accuracy, confusion patterns, and how useful the review queue is for finding true errors.

Invariant Metrics

How to read stability results

Flip rate

Each perturbed verdict is compared with its repeated-original baseline: a majority label or stable candidate ID, or a mean numeric score. Numeric disagreements require |perturbed − baseline| > saved tolerance, even if a threshold-derived label stays the same.

Noise floor

The repeated-original flip rate is reported as separate context. It is not subtracted from invariant flip risk.

Signed score shift

The average perturbed score minus the original baseline score. A positive shift is more lenient for a higher-is-better judge, and stricter for a lower-is-better judge. Stability alone is not an accuracy guarantee.

The headline invariant risk averages item-level risks; operator attribution pools individual comparisons. Missing or failed verdicts are excluded, not counted as agreement or zero risk. Check coverage and parse/transport failures alongside the rates.

Directional Metrics

How to read degradation detection

Directional detection

Each eligible item/variant case compares repeated verdicts: mean scores or majority labels. Any decrease in judged quality counts as detection, respecting the configured score direction; for binary judges, pass → fail counts. A rate of 0.705 means 70.5% of analyzable eligible cases were detected.

Noise-adjusted detection

For numeric judges, the quality drop must exceed the item's repeated-baseline score standard deviation. For binary judges, subtract the item's baseline flip rate from each detection credit, average, then floor the result at zero. This is descriptive, not a significance test.

Contradiction

An eligible degradation receives a better quality score or label instead of a worse one. Unchanged verdicts are misses, not contradictions. Cases without usable comparisons remain unavailable rather than becoming zero-rate evidence.

Eligibility is decided from repeated judge baselines, not gold labels. Binary baselines must pass; ordinal baselines must be outside the worst-score margin defined by invariant_tolerance. For example, a 1–10 higher-is-better scale with tolerance 1 requires a baseline mean above 2. This margin controls eligibility, not the detection threshold. Pairwise audits have no directional probes.

Walkthrough

How an audit works

1. Configure and select

Load the judge definition and evaluation items, then review the operator selection. Suggestions replace the built-in selection; they are not automatically added to manual choices. An empty selection can run baselines alone.

2. Judge the originals

Repeat the original cases to measure baseline noise and resolve directional eligibility before generation. Eligibility is separate from operator applicability and later validation.

3. Build candidate edits

Generate judge-wide variants once, and item-scoped variants for individual eligible items, using rules or an LLM. Selection is not a promise that every operator can run on every item; unsupported constructions are skipped.

4. Validate and save the suite

Structural edits need explicit guards. Semantic changes, including rule-built reasoning style and partial completion, need LLM validation in grading context. Save candidates, validation decisions, and accepted item/variant applications in suite.json before perturbed judging.

5. Judge accepted pairs

After the generation/validation checkpoint, judge only accepted item/variant pairs with the configured repeat count, then report accepted, rejected, skipped, and failed work separately.

6. Read the evidence

Reports keep invariant stability, directional degradation detection, gold-label correctness, and call-level examples in separate views.

Model Roles

Which model is doing what

Judge under test

The model being audited. The audit treats it as a black box and measures how its verdicts move.

Perturbation generator

Builds LLM-backed prompt, rubric, input, output, or paired rewrites from catalog instructions. Optional role overrides inherit the generator settings unless explicitly pinned.

Validator agent

Checks applicability and semantic admissibility using the full grading context. It must differ from the judge under test. It inherits the generator by default; hold it fixed across conditions when comparing generators.

Planner and summary agents

The planner proposes operator choices for review; the summary role explains report evidence. Both inherit generator settings unless overridden. Neither changes the judge verdicts or computed metrics.

Saved Workflows

Replay, regenerate, and reanalyse

mawile replay

Requires suite.json. Reuses saved items, variants, validation decisions, and application scope, then makes fresh baseline and perturbed judge calls. It does not plan, generate, or validate again. Judge calls can incur costs.

mawile report --regenerate

Renders saved metrics, interpretation, and traces offline. It makes no model calls and does not recompute metrics. Use it to refresh report presentation, not to update an analysis policy.

Paper offline reanalysis

scripts/paper_scripts/reanalyze_experiments.py reparses saved responses and recomputes metrics under an explicit recorded policy, without model calls. It reuses semantic validation decisions; it does not run a new semantic validation pass.

Config Semantics

Defaults that matter

Empty invariant list

perturbation_operators: [] selects no built-in invariants. Enabled custom operators are selected separately; an empty built-in list does not disable them.

Empty directional list

directional_perturbation_operators: [] selects no built-in directionals. With both lists empty and no enabled custom operators, the run is baseline-only.

Gold label field

data.gold_field points to trusted labels. Set it to null only when correctness should not be evaluated.

Custom and suggested choices

Suggestions replace the built-in choices for review. Enabled custom operators are additional explicit choices, still subject to applicability and validation. Pairwise custom operators must be invariant and target the judge prompt, rubric, or task input.

Pairwise audits support applicable judge/input invariants plus candidate-position swaps, not arbitrary candidate-output rewrites. Swaps preserve stable candidate identity and belong to the invariant category. No pairwise directional probes are supported, including custom ones.

Validation Types

Independent admissibility prompts

{{ validation_catalog|length }} prompts
Item edits

Validators receive original and edited transcripts plus the judge's instructions, rubric, and output semantics. A changed field is checked in its full grading context, not just for surface similarity.

Preserve existing errors

Invariant edits must preserve the response's existing correctness, mistakes, omissions, and task requirements. Repairing an incorrect original answer is not a meaning-preserving change.

Judge config

Prompt and rubric validators compare the original and edited judge instruments with dataset context. They check that grading criteria, requirements, and output semantics are preserved.

Gold labels

Gold standard labels are trusted inputs, not generated variants, so they feed correctness metrics rather than admissibility validation.

Rubric criterion reorder is structural only for an unambiguous flat set of independently labelled numeric rows such as 1: .... Explicitly delimited nonnumeric blocks need semantic validation; ambiguous or free-form rubrics are skipped.
